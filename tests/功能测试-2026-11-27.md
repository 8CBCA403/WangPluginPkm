# WangPluginPkm 功能测试记录

2026-11-27，在 Windows x64、.NET SDK 10.0.301 上测试了 main 的提交 `dfeeba0`。插件按 Release 配置编译。宿主从 PKHeX 的 `26.10.18` 标签构建，使用独立目录、项目规定的 DLL 和字体，以及一次性空白存档。宿主测试通过自动化调用实际 WinForms 菜单和按钮。

## 复现的功能问题

| 功能 | 最小复现步骤 | 实际结果与验收标准 |
| --- | --- | --- |
| 对战王的 Showdown 导入 | 在《剑》打开「对战王」，输入两行 `Pikachu` 和 `- Thunderbolt`，点「从Showdown批量导入」。 | 在导入确认前抛出 `MissingFieldException`，找不到 `PKHeX.Core.ShowdownSet.InvalidLines`。验收时，确认后编辑面板应显示会十万伏特的皮卡丘，并通过合法性检查。 |
| 变蛋器的训练家 ID | 在表 ID 为 `123456`、显示里 ID 为 `0` 的《剑》空白存档中，将伊布放到编辑面板，点「变蛋器 → 生成面板 → 生成蛋」。 | 面板收到伊布蛋，但表 ID 成了 `57920`。代码把六位表 ID 强制转为 16 位无符号整数。验收时蛋应保留原训练家的完整 ID。 |
| 全部箱子排序 | 在《剑》打开「工具 → 超王插件PKM」，查找 README 所述的「全部箱子排序」。 | 实际加载了 10 个一级菜单项，没有排序入口。仓库里的 `SortPlugin.cs` 整个实现被块注释包住，Release DLL 中也没有这个插件类型。若继续提供该功能，应能在一次性盒子中按所选图鉴顺序排序。 |
| 额外文件编辑器的 GP1 转 PB7 | 在《去皮》使用皮卡丘 GP1 文件，导入后点「转为PB7」。测试将合成样本传给文件选择后的同一个读取方法，然后点击窗体按钮。 | 同一文件经 PKHeX.Core 直接转换得到种类 `25`，插件回填种类 `0`。文件读取把数据复制进了 `gpm.Data.ToArray()` 生成的临时数组。验收时回填的应是皮卡丘。 |
| 打印检测报告 PDF | 保留默认设置，宝可梦图片地址前缀留空，使用种类编号 133 的伊布生成报告。测试直接执行盒子右键菜单调用的报告生成方法，已放置项目字体。 | 插件尝试把 `0133.png` 当作绝对 URI，抛出 `UriFormatException`，没有生成 PDF。验收时默认配置应能离线生成报告。 |
| 计算器反向转换闪光 PID | 在「多功能计算器 → 特殊计算」中，将 TID16、SID16 和 XOR 均设为 `0`，右侧输入闪光 PID `12341234`，点击向左箭头。 | 左侧得到同一个 `12341234`，用 PKHeX.Core 检查仍然是闪光。验收时转换结果应为非闪光。 |
| 计算器空 PID | 打开「多功能计算器」，将「通过PID算性格」的输入框留空，直接点对应的「计算」。 | 按钮抛出 `FormatException`。验收时空值应有输入反馈，用户仍可在同一窗口继续计算。作为对照，输入 `00000003` 返回 `3,Adamant`，十六进制 `FF` 转十进制返回 `255`。 |

对战王、变蛋器、排序菜单和两项计算器问题均在隔离 PKHeX 宿主中复现。GP1 和 PDF 案例分别验证了文件读取后的转换流程和报告生成方法。

## AutoMod 开源依赖对照实验

WangPluginPkm 当前提交附带的 `PKHeX.Core.AutoMod.dll` 和 `PKHeX.Core.Enhancements.dll` 程序集版本均为 `25.6.10.0`。它们与插件所用的 PKHeX.Core 26.10.18 混用时，对战王在创建 `RegenTemplate` 时访问了旧字段。

在独立副本中从开源仓库的 `26.10.18` 标签编译这两个依赖，替换副本中的两个 DLL 并重新构建插件。在相同宿主和空白《剑》存档中重复测试。单只对照从导入方法跳过确认弹窗，多只对照使用原窗体的批量导入按钮。[对应源码标签](https://github.com/santacrab2/PKHeX-Plugins/tree/26.10.18)

| 输入 | 仓库自带依赖 | 同版本开源依赖 |
| --- | --- | --- |
| 单只皮卡丘，招式 Thunderbolt | 抛出缺少 InvalidLines 字段异常 | 编辑面板种类 25、招式 85，PKHeX 合法性检查通过 |
| 皮卡丘与伊布两组 Showdown 文本 | 同样抛出缺少字段异常 | 回读当前盒子的前两个槽位，种类依次为 25 和 133 |

对照实验使用了独立副本，当时仓库源码与自带依赖仍处于原提交状态。对照覆盖了这两条导入流程。

## 修复后的回归

- 项目内置的 AutoMod、Enhancements 更新为上游正式版 `26.10.18`（提交 `b13c011bb0c4c3d475ca7f0a30b880f5b24dbed7`）。宿主中用对战王原按钮验证了单只和双只 Showdown 导入。
- 从《阿尔宙斯》切回《剑》后可打开变蛋器。伊布蛋保留表 ID `123456` 和里 ID `2`。
- 恢复「全部箱子排序」，并随存档更新菜单。切换《去皮》和《剑》时检查了可用排序选项。同一套《剑》测试数据用全国图鉴排序后为皮卡丘、敲音猴，用伽勒尔图鉴排序后为敲音猴、皮卡丘。
- 在《去皮》将合成 GP1 样本读取后通过「转为PB7」按钮回填，编辑面板获得种类为 `25` 的 PB7。
- 图片地址留空时，在宿主中成功生成包含 PDF 头和文件结束标记的本地报告。报告使用默认图片，并包含生成所需的 iText 适配器。
- 使用 PKHeX.Core 验证了计算器中 XOR `0–15` 的转换结果。反向计算均得到非闪光 PID，并保留 PID 低 16 位。
- 性格计算留空时显示「请输入有效的十六进制 PID」。关闭提示后在同一窗口输入 `00000003`，得到 `3,Adamant`。
- Release 构建为 0 警告、0 错误。含新增检查的四组回归通过，英文深色 23 项、英文浅色 21 项、简中深色 22 项、简中浅色 20 项。

## 第二轮补测

补测沿用 PKHeX 26.10.18 的隔离宿主与一次性存档。

| 功能 | 复现和验证 |
| --- | --- |
| RNG 种子计算 | 《绿宝石》Method 1 输入 `12345678` 得到 IV `10/12/22/7/29/0`。旧版输入 `XYZ` 抛异常，修复后显示输入提示。 |
| RNG 太晶检测 | 原按钮缺少点击事件。修复后在《剑》会提示使用《朱／紫》存档，在《朱》用已知种子对应的 EC 验证了可回推 `12345678`。该用例验证种子和 EC 的对应关系。 |
| 超级数据库覆写 | 旧版在《晶灿钻石》把存档误转为《剑／盾》类型。修复后在《晶灿钻石》和《阿尔宙斯》通过实际覆写按钮把指定皮卡丘改到 42 级。自动回归确认未选中的槽和空槽保留原样。 |
| 派送器 | 旧版在只剩一个槽时写入一只后抛出越界异常。修复后会检查完整容量，空位不足时提示并保留空槽，空位充足时写入 30 只伊布。《晶灿钻石》的速配努力值也从类型转换异常恢复为可写入。 |
| 图鉴制作器和闪光器 | 在《剑》中生成洛托姆多种形态，并验证 SID16 闪光操作后读取盒中皮卡丘确为闪光。 |
| 对战王 PokePaste | 公开队伍可下载，但 AutoMod 正式版在《朱》中导入时会因 `EntityContext.None` 报错。把内置的 AutoMod 和 Enhancements 固定到正式版后的 `26.10.19` 提交后，使用原网页导入按钮将同一个公开链接里的 6 只宝可梦写入盒子。PKHeX 依然使用 26.10.18。[AutoMod 对应修复](https://github.com/santacrab2/PKHeX-Plugins/commit/f5a6f2ce80f24881563661639d7d0ae158c6bb63) |
| 对战王 HOME | 修正排名详情和头像异步加载的选中项与窗口生命周期处理。在宿主正常消息循环中读取到 82 条赛季记录，抽查一个赛季返回 1,000 条排名，并验证选中排名行后能显示名次并关闭窗口。 |

Google Sheets API 在没有配置 API Key 的测试环境返回 HTTP 403，表格网页可访问。带凭据读取及长时间 RNG 搜索未做端到端验证。

最终 Release 构建为 0 警告、0 错误。英文深色、英文浅色、简中深色、简中浅色四组回归分别通过 26、24、25、23 项断言。
